Godot 3 habits, caught before Godot sees them

Models trained on years of Godot 3 tutorials still write yield, export var and KinematicBody2D. The review names every line and gives the Godot 4 fix.

old_player.gd
1extends KinematicBody2D
2
3export var speed = 200
4onready var sprite = $Sprite
…
11	yield(get_tree().create_timer(1.0), "timeout")
…
17	velocity_old = move_and_slide(velocity_old, Vector2.UP)
18	rotation = deg2rad(90)
19	var t = OS.get_ticks_msec()
godot_review
  • :1error Cannot extend "KinematicBody2D". In Godot 4 it is CharacterBody2D.
  • :3error export var is @export var in Godot 4.
  • :4error onready var is @onready var in Godot 4.
  • :11error yield() is await in Godot 4.
  • :17error move_and_slide() takes 0 arguments, but 2 are given. Set velocity and call it without arguments.
  • :18error deg2rad() is deg_to_rad in Godot 4.
  • :19error OS.get_ticks_msec() moved: use Time.get_ticks_msec().

43 MCP tools, one CLI

Most of the 43 tools are also CLI commands, so they work from any shell or agent. Output is compact and stable, so it is cheap for a model to read. Every write shows the change first, and godot_undo takes it back.

Explore the complete tool inventory +
  • godot_scan

    Map the project without starting Godot: scenes and node trees, scripts with signals and exports, autoloads, input map, broken references.

    godotwright scan
  • godot_api

    Exact Godot 4.7 lookup from the bundled class reference (1078 classes): signatures, inheritance, Godot 3 names.

    godotwright api Node2D.look_at
  • godot_api_search

    Search the reference in plain words, so the agent finds is_on_floor() instead of guessing.

    godotwright api --search "is on floor"
  • godot_review

    AAA review with a 0–100 score for api, performance, quality and structure. Also reviews unsaved code before the agent writes it.

    godotwright review --min-score 90
  • godot_check

    Run Godot headless: import, load and instantiate every script and scene, optionally run the main scene. Errors come back as file:line.

    godotwright check --run
  • godot_usages

    Every place a name or res:// path is used: code, scenes, signal connections, groups and settings. Call it before renaming or deleting.

    godotwright usages take_damage
  • godot_diff

    A diff by meaning against git: nodes, properties, connections, script functions and exports, and what the change breaks elsewhere, such as a scene connection to a function that is gone.

    godotwright diff
  • godot_impact

    What a change reaches: the scenes that load the changed files, the tests and saved scenarios that cover them, and the checks to run.

    godotwright impact
  • godot_collisions

    Physics layers and masks by name and bit value: who detects whom, the exact mask to set, and what can never work.

    godotwright collisions --between Player Enemy
  • godot_rename

    Rename a function, signal, node, action or file everywhere at once, keeping connections, node paths and .uid files right.

    godotwright rename hp health --write
  • godot_project_edit

    Change settings, input actions and autoloads in project.godot, checked against Godot 4.7, touching only that entry.

    godotwright project input add jump --key Space
  • godot_scene_edit

    Add or remove nodes, set properties, connect signals and attach scripts in a .tscn, without the editor.

    godotwright scene add main.tscn . Music AudioStreamPlayer
  • godot_migrate

    Rewrite Godot 3 GDScript to Godot 4 where that is mechanical, and list what is left to do by hand.

    godotwright migrate --write
  • godot_test

    Run GUT or GdUnit4 tests headless and show only what failed, with file:line.

    godotwright test
  • godot_play

    Run a scene with an input timeline and print the values you watch per frame: the agent sees the game do something.

    godotwright play --input "10 tap jump" --watch Player.position
  • godot_scenario

    Keep a passing play run as a regression test in the project, and run them all with every failing claim, its value and frame.

    godotwright scenario --save jump --input "10 tap jump" --expect "Player.velocity.y < 0 @ 10"
  • godot_screenshot

    Render a scene or a model to a PNG and say how much of the picture is drawn.

    godotwright screenshot --scene res://main.tscn -o shot.png
  • godot_doctor

    Start here when something is broken: the review and Godot grouped by cause, most urgent first, each with the lesson that explains it and the fix, then numbered next steps.

    godotwright doctor --symptom "falls through the floor"
  • godot_fix

    Apply the mechanical fixes for review findings, each labelled safe or check. Shows them first, then reviews the changed files again.

    godotwright fix --write
  • godot_code

    Godot's own GDScript language server, kept warm: warnings at the project's levels, inferred types, definitions and completion, also for code that is not saved yet.

    godotwright code diagnostics res://player.gd
  • godot_deps

    The project as a graph of files from where the game starts: unused files with their size (paths the code builds count), why a file is used, what a scene loads, and scene loops Godot cannot load.

    godotwright deps unused
  • godot_undo

    Undo the last Godotwright writes, newest first: edits, renames with their moves, migrations, fixes and model builds. A file changed by hand since is left alone.

    godotwright undo --steps 2
  • godot_session

    Load a scene once, headless and paused, and keep the game running between calls: a world that takes a minute to load loads once.

    godotwright session start
  • godot_game

    Drive that running game: live tree, get and set values, step frames with input until a condition holds, 3D layout, rays, UI issues per window size, and hot reload of edited scripts with every node's values kept.

    godotwright game step 120 --until "Hero.is_on_floor() == true"
  • godot_perf

    Frame times as a player feels them: p50/p95/p99 against a budget, the slowest frames and what changed on them, and the change since the last run.

    godotwright perf --scene res://level.tscn
  • godot_export

    Before an export: files the presets leave out although the game loads them, and plain data files Godot only exports when include_filter names them.

    godotwright export
  • godot_checklist

    Every AAA rule with its fix, so the agent knows the bar before it starts. MCP only: there is no CLI command.

  • godot_feedback

    Mark a finding as wrong or right, or say whether a lesson helped. Later reviews on this machine learn from it.

    godotwright learn feedback
  • godot_lessons

    Lessons from real Godot projects: symptom, cause, fix and test, by words, Godot error or rule. gaps lists what Godotwright cannot predict yet.

    godotwright lessons moving ship deck
  • godot_lesson_add

    Keep a lesson learned here, scrubbed of names, paths and code. It comes back when the same error does; nothing is sent.

    godotwright lessons add --title "..." --fix "..."
  • godot_dream

    Look back between sessions: draft lessons for errors that keep coming back, "use X, not Y" hints for guessed API names, lessons to merge or retire, each with its evidence. Local, no model; nothing changes until you apply, and undo takes it back.

    godotwright dream --apply 1,3
  • godot_model_brief

    One page before a small model builds anything: the kind to start from, parts, size, rules and the order of tools.

    godotwright model brief "a helicopter"
  • godot_model_identify

    What a thing is: parts, pivots, typical size with its source, variants and what to anticipate. English or Dutch.

    godotwright model identify "a tractor"
  • godot_model_spec

    The model spec format, an example and the ready-made kinds.

    godotwright model spec
  • godot_model_library

    Over a thousand ready-made base recipes: furniture, street, storage, nature, buildings, vehicles and props. Build one by id, or start your own from its spec.

    godotwright model library "oak chair"
  • godot_model_build

    Build a clean .glb from a kind or a spec, with UVs, tangents and a node per part, then lint it.

    godotwright model build house -o house.glb
  • godot_model_view

    See a .glb as text: front, side and top views made of letters, the parts with sizes, and parts that do not touch.

    godotwright model view car.glb
  • godot_model_lint

    Score a .glb. With an archetype it also checks the model is what it should be.

    godotwright model lint car.glb --archetype car
  • godot_model_inspect

    What is in a .glb: nodes, triangles, textures and size.

    godotwright model inspect car.glb
  • Mods and patches

    Review a mod against the game it patches, from its source folder or a .pck file list.

    godotwright review mod/ --base game/
  • Local learning

    Rules real Godot keeps contradicting turn into hints. Nothing leaves your machine unless you opt in.

    godotwright learn

Before you jump in

A few good questions.

Does it need Godot installed?

No for scan, api, review, migrate and the edits: they read your project files and the bundled Godot 4.7 class reference. check, test, play and screenshot run Godot 4.7 headless (--godot <path>, $GODOT, godot on your PATH, or a Godot 4 download it finds in the usual folders, Steam or Downloads).

Which agents does it work with?

Any agent that speaks MCP over stdio. CI connects Claude Code and Codex to the server on every push. The CLI works from any shell, so agents without MCP can call it too.

Does it send my code anywhere?

No. Learning stays on your machine and stores counters, rule names and API names, never code, names or paths. Sharing anonymous counters is opt-in, off by default, and respects DO_NOT_TRACK. See PRIVACY.md.

Will it help me port a Godot 3 project?

Yes. The review flags Godot 3 syntax and names such as export var, yield, KinematicBody2D, deg2rad and move_and_slide() with arguments, and gives the Godot 4 replacement for each.

Does it work with Godot 4.0–4.6?

The target is Godot 4.7.x. Most findings apply to every Godot 4 version, but API lookups answer for 4.7, so a method added after your version may be reported as present.

Does it work next to other Godot MCP servers?

Yes. Most Godot MCP servers drive the open editor through an addon. Godotwright works from files, without the editor, and checks what the agent writes. Use both: an editor server to drive the editor, Godotwright to check the code.

Does it write my game?

No. It checks, runs and fixes what you or your agent write, and builds clean base 3D models to refine. It does not replace playtesting or your own judgement.

Is it on npm?

Yes: godotwright. npx -y godotwright runs the latest version, or install it with npm install -g godotwright.
