Claude Code plugin · Godot 4.7

Claude Code, checked in Godot 4 after every edit.

One command puts Godotwright in Claude’s loop. Every Godot file Claude edits is reviewed right after the edit, Godot errors come back with the lessons that explain them, and Claude does not stop with review errors left open. With the MCP tools, ten skills and two subagents.

/plugin install godotwright --marketplace laaielichter/Godotwright

Start Claude Code in your Godot project folder. Needs Node.js 22.12 or newer. On Claude Code older than 2.1.275: /plugin marketplace add laaielichter/Godotwright, then /plugin install godotwright@godotwright.

Four hooks: Claude does not have to remember a tool

An agent with a toolbox still forgets to use it. Hooks run on their own at fixed moments. They say nothing when they have nothing to add, never fail the agent, and GODOTWRIGHT_HOOKS=0 turns them off.

  • At the start

    session-start

    A session in a Godot project starts with its name, Godot version, renderer, scripts, scenes, main scene, autoloads, and whether Godot is installed for the tools that run it.

  • After an edit

    post-edit

    After an edit of a .gd, .tscn, .tres, .gdshader or project.godot file, that file is reviewed. Errors go back to Claude at once, with the lessons behind them; warnings come as a note.

  • After a command

    post-bash

    When a command’s output holds Godot errors (SCRIPT ERROR, Parse Error, …), the lessons from real projects that explain them are added.

  • Before stopping

    stop

    Review errors still open in Godot files changed in this session are named once, before Claude says it is done.

Ten skills

Seven Claude uses on its own when the work calls for them, and three you start yourself. Each one leans on the MCP tools and on 272 lessons from real Godot 4 projects.

  • Any Godot work

    godot

    The workflow: map the project, look up the exact Godot 4.7 API instead of guessing, review before and after each edit, check with Godot before finishing.

  • Errors and wrong behaviour

    debug

    From a Godot error, a crash or a body falling through a floor to the cause, the fix and the proof.

  • Stutter and load times

    perf

    Stutter, hitches, slow loading, low fps and memory: measured first, one fix at a time, measured again.

  • Things that move

    vehicles

    Helicopters, aircraft, cars, trains, ships, moving platforms and decks, landing and docking, and the cameras that follow them.

  • Large worlds

    world

    Terrain, streaming, levels of detail, road, rail and water networks, and precision far from the origin.

  • 3D models

    model

    Build a model from code, look at it as text and pictures, and lint it against what the thing really is.

  • Shipped games

    patch

    Mods, overlays, installers and hotfixes to a shipped game, with preflight checks, receipts and rollback.

  • You start it

    /godotwright:review

    Review the project and fix what it finds, errors first, re-reviewing after each fix.

  • You start it

    /godotwright:port

    Port Godot 3 GDScript to Godot 4.7, then check it with a review and with Godot.

  • You start it

    /godotwright:learn

    Teach Godotwright what this session learned, anonymously, so the next session starts smarter. Nothing is sent.

Two subagents for work that would flood the conversation

  • godot-reviewer

    Reviews a change (GDScript, scenes, shaders, settings, models) with Godotwright and, when installed, with Godot itself. It checks every finding against the code and the 4.7 API and returns only confirmed problems with their fixes.

  • godot-debugger

    Finds the root cause of an error, a crash or wrong behaviour with the lessons, the project map, the 4.7 API and headless Godot runs, and proves it.

What it runs, writes and sends

  • Runs: npx -y godotwright@0.5.0 mcp --tier premium, an exact version of the npm package, published from the repository by GitHub Actions with provenance. The tools that run Godot (check, test, play, screenshot) run your Godot 4.7 headless on your project.
  • Hooks: run node with the plugin’s hooks/run.mjs, which starts the same pinned version. They read the file you edited and the output of commands, and keep a small state file per session.
  • Writes: only inside your project. Tools that change files show the change first and write only when asked.
  • Sends: nothing. There is no telemetry; opt-in sharing of anonymous counters is off by default (PRIVACY.md).

FAQ

Can I turn the hooks off?

Yes. Set GODOTWRIGHT_HOOKS=0. The MCP tools, skills and subagents keep working.

I only want the MCP server, without skills and hooks.

claude mcp add godotwright -- npx -y godotwright mcp --tier premium

I use Codex, Cursor or another agent. Can I get the same?

The MCP server works in any MCP client; see the install page. The hooks are a CLI command, godotwright hook <event>, that reads Claude Code’s hook JSON on stdin, so any agent with a similar hook system can call it.

Does it need Godot installed?

Not for the review, the API lookups, the project map, migrate or the edits. check, test, play and screenshot need Godot 4.7; set GODOT to its path if it is not found in the usual install folders.

Does it work next to an editor-driving Godot MCP server?

Yes. Those drive the open editor through an addon; Godotwright works from files and checks what Claude writes.
